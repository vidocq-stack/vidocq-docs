= Tutorials
:description: Step-by-step, end-to-end guides for building applications with the Vidocq runtime.

[.lead]
These tutorials walk you through building real applications with Vidocq, one step at a time. Each one is self-contained, starts from an empty directory (or from the previous tutorial), and is written for Vidocq `{project-version}`: every command has been run with the CLI of that version, and the CLI writes the `pom.xml` and `module-info.java` changes each step needs.

== Health checks

Add the runtime extension in your application directory:

[source,bash]
----
vidocq extension add knock-health
vidocq start
----

Request `/health` in another terminal. An application with no custom checks responds with `{"status":"UP","checks":[]}`.
See xref:your-first-app.adoc#step-7-add-extensions-as-you-grow[the worked example] or xref:{page-component-version}@knock::getting-started.adoc[use Knock standalone].

== PostgreSQL

To connect a REST application to PostgreSQL, follow xref:rest-and-database.adoc[the database tutorial].
It provisions PostgreSQL in a container for development and tests, creates a table with Flyway, and verifies the result with a request to `/products`.

== JWT authentication

Add `cervantes-jwt` with `vidocq extension add`, then follow xref:{page-component-version}@cervantes::usage.adoc[JWT configuration and roles].

[#change-port]
== Change the HTTP port

From the application directory, set the port and start the application:

[source,bash]
----
vidocq config set vidocq.http.port 9090
vidocq start
----

For the tutorial application, `curl http://localhost:9090/hello` now returns `Hello from Vidocq!`.
Stop the application and set the property back to `8080` to continue the tutorial.

For application settings of your own, see xref:{page-component-version}@ravel::getting-started.adoc[MicroProfile Config].
