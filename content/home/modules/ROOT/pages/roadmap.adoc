= Vidocq ecosystem consolidated roadmap
:description: Per-module status and upcoming milestones.

[.lead]
This page aggregates the progress of all twenty-two modules — fourteen Jakarta EE bricks (including the Vidocq Runtime orchestrator) plus eight MicroProfile implementations. Each section links to the module's documentation for details. The suite is released on Maven Central, all the modules together under one version (Erasmus and Tassis are not released yet) — an alpha, APIs may still change.

== Detailed status by module

=== Chappe — HTTP transport

* **Done**: HTTP/1.1 and HTTP/2 conformant to RFC 9110/9112/9113, WebSocket (RFC 6455), gRPC transport framing over HTTP/2, virtual threads, zero dependency.
* **Coming up**: HTTP/3 / QUIC, an explicit rewrite and redirect table.
* Details: xref:chappe::index.adoc[Chappe].

=== Vauban — CDI 4.1 Lite

* **Done**: build-time injection graph resolution, Maven plugin, JUnit integration, Class-File API + APT generation, class loader and application layer (Java SE launcher, Vidocq dev mode), official CDI 4.1 Lite TCK **774/774**.
* **In progress**: `ScopedValue` propagation for scoped contexts.
* **Coming up**: CDI 4.1 Full (beyond Lite).
* Details: xref:vauban::index.adoc[Vauban].

=== Champollion — JSON-P / JSON-B

* **Done**: JSON-P 2.1 — official TCK **179/179**, JSON Pointer, Patch and Merge Patch included; JSON-B 3.0 — official TCK **290/295**, no failure (the 5 others are disabled in the TCK itself); JSON-B bindings generated by APT.
* **Deferred**: the JSON-B TCK run on the generated bindings (static mode).
* Details: xref:champollion::index.adoc[Champollion].

=== Foy — Servlet 6.1

* **Done**: official Jakarta Servlet 6.1 TCK — **1707 passing of 1714 run**, no failure (the 7 skipped are HTTP/2 server push); Chappe transport integration, Vauban CDI integration; Jakarta WebSocket 2.2 server, programmatic API, on Chappe's WebSocket.
* **Coming up**: Jakarta WebSocket 2.2 annotated endpoints and its official TCK.
* Details: xref:foy::index.adoc[Foy].

=== Cassini — Jakarta REST 4.0

* **Done**: official REST 4.0 TCK green on every test that applies to the Core Profile (xref:cassini::tck.adoc[TCK status]), SSE real-time streaming, client API, Chappe transport integration, Champollion entity providers, optional Vauban CDI, `@RolesAllowed` with MicroProfile JWT (via xref:cervantes::index.adoc[Cervantes]).
* **In progress**: performance and footprint (hot-path allocations, end-to-end benchmarks).
* Details: xref:cassini::index.adoc[Cassini].

=== Mansart — Jakarta Data + Transactions

* **Done**: Jakarta Data 1.0 — official TCK **74/74**, virtual-thread-native JDBC pool, named datasources (`dataStore` routing), Jakarta Transactions 2.0 transaction manager, `@Transactional` via Vauban.
* **In progress (M6c)**: full Jakarta Transactions 2.0 TCK suite.
* **Moved**: Jakarta Persistence 3.2 left Mansart for xref:noether::index.adoc[Noether] on 2026-10-11. `mansart-jakarta-data` already covers everyday needs in Vidocq.
* Details: xref:mansart::index.adoc[Mansart].

=== Erasmus — Jakarta Validation 3.1

Not released yet.

* **Done**: bootstrap (`Validation.buildDefaultValidatorFactory()`), the 21 built-in constraints, custom and composed constraints, message interpolation (EL subset, EN/FR bundles), cascaded validation of a nested bean (`@Valid`), groups and group sequences.
* **Coming up**: container element constraints (`ValueExtractor` SPI), executable validation, APT static codegen, CDI (Vauban) and Jakarta REST (Cassini) integration, official TCK, first release.
* Details: xref:erasmus::index.adoc[Erasmus].

=== Noether — Jakarta Persistence 3.2

Preview, new in 0.4.0: released, not certified.

* **Done**: Jakarta Persistence 3.2 provider with entity access generated at build time, H2 and PostgreSQL dialects, on Mansart's pool and transactions, optional CDI integration; Vidocq Runtime extension; official Persistence TCK: **2131 of 2135** pass, no failure, 4 skipped by the TCK, with one fixture backported from upstream — a local run, not a certification.
* **Coming up**: Jakarta Persistence 3.2 certification.
* Details: xref:noether::index.adoc[Noether].

=== Kerckhoffs — Jakarta Security 4.0

Preview, new in 0.4.0: released, not complete and not certified.

* **Done**: identity stores (in-memory store, `Pbkdf2PasswordHash`), the built-in BASIC and FORM mechanisms, an application's own mechanism, `SecurityContext.authenticate`, `@RememberMe`, Jakarta Authorization for web resources; Vidocq Runtime extension, on Foy and Vauban.
* **Coming up**: OpenID Connect, the custom FORM mechanism, the database and LDAP identity stores, the full official TCK (xref:kerckhoffs::tck.adoc[TCK status]).
* Details: xref:kerckhoffs::index.adoc[Kerckhoffs].

=== Peano — Jakarta Expression Language 6.0

New in 0.4.0.

* **Done**: grammar, operators, coercions, functions, method expressions, lambdas and collection operations, build-time accessors and compiled expressions; official EL 6.0.1 TCK **361/361**; Vidocq Runtime extension.
* **Coming up**: certification.
* Details: xref:peano::index.adoc[Peano].

=== Ibarra — Jakarta Pages 4.0

New in 0.4.0.

* **Done**: runtime and parser, build-time page generation (Maven plugin), custom tags and tag files, Foy HTTP binding, TLD listeners, compiled EL on Peano; official Pages 4.0 TCK **682/682**; Vidocq Runtime extension.
* **Coming up**: Class-File API generation for scriptless pages, benchmarks, certification.
* Details: xref:ibarra::index.adoc[Ibarra].

=== Bodoni — Jakarta Standard Tag Library 3.0

New in 0.4.0.

* **Done**: the five libraries (`c:`, `fmt:`, `fn:`, `x:`, `sql:`) as portable tag handlers, on the Standard Tag Library API alone; the official Tags tests pass **541/541** on Ibarra, Foy and Peano — a compatibility measurement, not a certification; the same jar runs in a WAR on Open Liberty; Vidocq Runtime extension.
* **On standby**: build-time inlining of the core tags by Ibarra.
* Details: xref:bodoni::index.adoc[Bodoni].

=== Tassis — Jakarta Messaging 3.1

Not released yet.

* **Done**: classic, simplified and legacy domain-specific APIs on an in-memory broker of its own; the broker opened to the network over AMQP 1.0, with TLS, for the Tassis client and for any other AMQP 1.0 client; connection pool; `JMSContext` injection on Vauban; official Messaging 3.1 TCK **903/903** of the tests that apply to a Java SE provider, in the JVM and through the network.
* **Coming up**: XA and JTA, first release.
* Details: xref:tassis::index.adoc[Tassis].

=== MicroProfile layer

Eight independent MicroProfile implementations, each wired into Vidocq Runtime through the extension SPI and, where relevant, exposed over Cassini.

The assembled runtime passes **1888 official MicroProfile TCK tests** across these eight specs: the seven of the MicroProfile 7.2 platform (OpenAPI and Telemetry on their release-candidate TCKs) plus Metrics 5.1 (see the xref:vidocq::tck.adoc[runtime TCK page]).

* xref:ravel::index.adoc[Ravel] — MicroProfile Config 3.1. TCK green (378 tests on the assembled runtime).
* xref:knock::index.adoc[Knock] — MicroProfile Health 4.0. TCK green (28 tests).
* xref:dirac::index.adoc[Dirac] — MicroProfile Metrics 5.1. TCK green (127 tests).
* xref:heisenberg::index.adoc[Heisenberg] — MicroProfile Fault Tolerance 4.1. TCK green (463 tests).
* xref:cervantes::index.adoc[Cervantes] — MicroProfile JWT 2.2. TCK 208/208; `@RolesAllowed` wired into Cassini.
* xref:cyrano::index.adoc[Cyrano] — MicroProfile Rest Client 4.0. TCK 235/235 (SSL and SSE included).
* xref:humboldt::index.adoc[Humboldt] — MicroProfile Telemetry 2.2. TCK 85/85 (release-candidate TCK); trace/metric/log SDKs, OTLP-HTTP exporter, W3C propagation; gRPC export post-MVP.
* xref:grimm::index.adoc[Grimm] — MicroProfile OpenAPI 4.2. TCK green (364 official tests, release-candidate TCK).

=== Vidocq Runtime — orchestrator

* **Done**: bootstrap, lifecycle, `VidocqExtension` SPI, extensions for the bricks (HTTP server, Servlet, WebSocket, REST, Expression Language, Pages, Standard Tag Library, Data, pool, transactions, Persistence, Security, and the eight MicroProfile specs), dev mode, CLI, Maven plugin (jlink / jpackage / Docker), Jakarta EE Core Profile 11 compatibility request filed and accepted.
* **Coming up**: production readiness for 1.0.0 (fuzzing, soak and chaos tests, end-to-end benchmarks, security audit), a GraalVM `native-image`, and a goal that records the JDK's AOT cache (Project Leyden), which works by hand today.
* Details: xref:vidocq::index.adoc[Vidocq Runtime].

== Track progress

Reproducible bugs and performance numbers are recorded in each component's folder (at the root of the Erasmus and Tassis repositories):

* `BUG.md` — reproducible bugs, hypotheses, status.
* `BENCH.md` — JMH/wrk/comparative runs, deltas vs previous run.

Official TCKs run behind each component's `tck` Maven profile, most of them through a `run-official-tck-*.sh` script in the component's folder or its TCK module (Vauban: `run-tck.sh`). A pull request runs none: the monorepo's `TCK nightly` workflow runs them once a day, on demand, and for a release.
